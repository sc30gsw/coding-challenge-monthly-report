# Revision は Report の複製として表す

確定済み Report に誤りが見つかったときの修正版は、履歴テーブルや専用の版テーブルではなく、**Report 行と ReportLine 行を丸ごと複製した新しい Report** として作ります。系列は `series_id`（最初の版の識別子）でまとめ、`version` で順序を持ちます。複製元は `superseded` になり、内容は不変のまま残ります。新しい版は `draft` から始まります。

ADR-0007 により、明細は版ごとに再編集され、承認され直す必要があります。版を読み取り専用のスナップショットとして持つ設計では、この導線が書けません。複製にすれば「Report とは何か」が版によらず同じ形になり、一覧・詳細・承認・確定のフローをそのまま再利用できると判断しました。

## 採らなかった案

- **`report_revisions` 別テーブル** — 版の一覧は取りやすいですが、明細を版ごとに編集・再承認する経路を別途作ることになり、モデルが二重化するため見送りました。
- **履歴テーブル + トリガによる自動記録** — 監査には向きますが、業務上の「修正版を作る」という明示的な行為を表現していないため見送りました。

## 影響

- `unique(series_id, version)` で版番号の重複を防ぎます。
- **`series_id` に対して進行中（`draft` / `in_review`）の版は最大 1 つ**、を部分ユニークインデックスで強制します。同じ系列に修正版が 2 つ並走する事故を DB で止めるためです。
- 系列をまたいだ集計（取引先ごとの月次合計など）では、`superseded` を除外し最新の確定版のみを見る、という条件を毎回書くことになります。ビューを 1 枚用意して隠します。
