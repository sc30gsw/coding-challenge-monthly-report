# UI は Mantine を主にし、レイアウトは Tailwind に分ける

**決定:** 複合 UI は Mantine（`@mantine/core` / `@mantine/hooks`）とします。レイアウトは Tailwind 4 です。衝突は `tailwind-preset-mantine` で吸収します。トークンの正は Mantine です。

## なぜ Mantine か

テーブル・モーダル・フォーム・通知・日付など、この業務アプリが要する UI の幅が広いです。対応できる幅が最も大きいコンポーネントライブラリだと判断し、採用しました。ヘッドレスから 1 つずつ組む時間は、版管理の深掘りから奪われると考えました。今足りるだけでなく、帳票や通知を足す将来の拡張にも Mantine UI は優れていると考えました。

## なぜ Tailwind か

レイアウト（flex / grid / 余白）を短く当てられたり、特定の部分だけスタイルを上書きしたい場合に、開発効率が上がると判断しました。

## オーバースペックでは？

デザインシステムを二枚持っているのではなく、役割を分けました。Mantine は今の業務 UI の幅を自作せずに埋めるためで、その時間を版管理に使う判断です。Tailwind は Mantine が持たないラッパーのレイアウト・特定スタイル専用です。将来の拡張性は、今の幅を自作しないことの次に来る利点だと考えました。

## 採らなかった案

- **Tailwind 単独 + headless** — 依存は最小ですが、コンポーネント自作が積み上がり、深掘りの時間が削られるため見送りました。
- **Mantine 単独（Tailwind を外す）** — 既存の `cn`（cnfast）と oxfmt のクラス整列を捨てるコストが乗るため見送りました。

## 影響

- `src/styles.css` は `tailwind-preset-mantine` を import します。素の `@import "tailwindcss"` は書きません。
- 同じ関心を両方で書きません。
